# WukongAutoBench

Консольная утилита на C# (.NET 10), которая автоматически прогоняет **Black Myth: Wukong Benchmark Tool** (Steam AppID 3132990) дважды — **CPU-тест** и **GPU-тест** — и выдаёт сводный отчёт: характеристики ПК, результаты обоих проходов, использованные настройки и проверку, что бенчмарк действительно с ними работал.

```
WukongAutoBench.exe          ← всё: поиск бенчмарка → CPU-тест → GPU-тест → восстановление настроек → отчёт
```

## Быстрый старт

1. Установите в Steam бесплатный **Black Myth: Wukong Benchmark Tool** (утилита может сама открыть установку: `WukongAutoBench.exe --install`).
2. Запустите Steam.
3. Запустите `WukongAutoBench.exe` (двойным кликом или из терминала) и **не трогайте мышь и клавиатуру ~10 минут** — утилита сама нажимает кнопки в меню бенчмарка.
4. Отчёт выводится в консоль и сохраняется в `results\<дата_время>\`:

```
results\2026-10-08_14-30-00\
├── report.md                      ← отчёт в Markdown
├── report.json                    ← то же в машиночитаемом виде
├── run.log                        ← лог прогона
├── GameUserSettings.original.ini  ← ваши настройки до прогона
├── cpu\benchmark_result.json      ← сырой результат бенчмарка
├── cpu\GameUserSettings.applied.ini
├── gpu\benchmark_result.json
└── gpu\GameUserSettings.applied.ini
```

### Сборка из исходников

Нужен [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0).

```powershell
dotnet run --project src/WukongAutoBench            # запустить сразу
dotnet test                                          # юнит-тесты

# один exe без зависимостей (не требует установленного .NET):
dotnet publish src/WukongAutoBench -c Release -r win-x64 --self-contained `
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true -o publish
```

### Параметры

| Параметр | Назначение |
|---|---|
| `--game-dir <путь>` | папка бенчмарка, если автопоиск по библиотекам Steam её не нашёл |
| `--only cpu\|gpu` | выполнить один проход |
| `--launch exe\|steam` | запуск напрямую exe (по умолчанию) или через `steam -applaunch 3132990` |
| `--cpu-resolution 1280x720` | разрешение CPU-теста |
| `--gpu-resolution 2560x1440` | разрешение GPU-теста (по умолчанию — текущее разрешение монитора) |
| `--menu-delay <сек>` | пауза между появлением окна и первым нажатием (по умолчанию 20; увеличьте на медленном диске) |
| `--timeout <мин>` | предельное время одного прохода (по умолчанию 20) |
| `--cooldown <сек>` | пауза между проходами (по умолчанию 15) |
| `--start-button x,y` / `--confirm-button x,y` | координаты кнопок меню в долях окна, если клики промахиваются |
| `--dry-run` | ничего не запускать, только показать изменения конфига (копии кладутся в `results`) |
| `--from-results <cpu> [gpu]` | построить отчёт по готовым файлам результатов бенчмарка |
| `--out <папка>` | куда писать отчёты |
| `--no-pause` | не ждать Enter в конце |

Коды выхода: `0` — оба прохода успешны, `1` — какой-то проход не удался, `2` — неверные параметры, `3` — бенчмарк не установлен, `130` — прервано Ctrl+C.

## Как это работает

| Этап | Реализация |
|---|---|
| Поиск бенчмарка | Steam из реестра → `libraryfolders.vdf` → `appmanifest_3132990.acf` (`installdir`, `buildid`) |
| Настройки | `<папка бенчмарка>\b1\Saved\Config\Windows\GameUserSettings.ini` (и `%LOCALAPPDATA%\b1\...`, если есть). Меняются только нужные строки, кодировка и порядок сохраняются |
| Запуск | `b1.exe -dx12` из папки бенчмарка (или через Steam). Steam при необходимости запускается в фоне |
| Старт теста | У бенчмарка нет ключа командной строки для автостарта, поэтому меню проходится эмуляцией ввода (`SendInput`): **Enter** на заставке → клик **«Тест быстродействия»** → клик **«Подтвердить»**. Координаты — доли клиентской области окна, поэтому не зависят от разрешения. Ввод отправляется только когда окно бенчмарка на переднем плане |
| Ожидание результата | Бенчмарк по окончании теста пишет JSON в `%TEMP%\b1\BenchMarkHistory\Tool\<unix-время>`. Утилита запоминает уже существующие файлы и ждёт новый, который полностью записан и разбирается как JSON |
| Завершение | Процесс бенчмарка завершается принудительно (при штатном выходе игра перезаписывает ini). Если бенчмарк закрылся сам без результата — до 3 перезапусков |
| Восстановление | Перед первым проходом создаётся копия ini (`*.wukongautobench.bak`), после прогона — восстанавливается. Это происходит и при ошибке, и по Ctrl+C, и при закрытии окна консоли; если утилиту убили — при следующем запуске |
| Характеристики ПК | WMI + реестр + WinAPI: CPU (ядра/потоки/кэш), GPU (VRAM из реестра драйвера, версия драйвера), RAM (модули, частота), материнская плата/BIOS, ОС, монитор, диск с бенчмарком (SSD/HDD), план питания, HAGS |

### Где настройки хранятся в ini

Значения дублируются в трёх местах, и утилита пишет все три синхронно — иначе игра при старте «откатит» часть из них:

| Где | Что | Пример (CPU-тест) |
|---|---|---|
| `[/Script/GSGameSettings.GSGameUserSettings]` | стандартные поля UE: разрешение, режим окна, VSync, лимит FPS | `ResolutionSizeX=1280`, `FullscreenMode=0`, `bUseVSync=False`, `FrameRateLimit=0.000000` |
| `UISettingData=(("Key", "Value"),...)` там же | значения меню бенчмарка (1 = Low … 5 = Cinematic) | `QualityLevel=1`, `ViewDistance=5`, `ImageQuality=360` (высота рендера = 720 × 50%), `Rtx=0`, `InsertFrame=0` |
| `[ScalabilityGroups]` | группы качества UE (`sg.* = значение меню − 1`) | `sg.ResolutionQuality=50`, `sg.ShadowQuality=0`, `sg.ViewDistanceQuality=4` |

### Какие метрики выводятся

Из самого бенчмарка: **средний / минимальный / максимальный FPS, FPS95**, средняя загрузка CPU и GPU, видеопамять, а также его собственные сведения о системе (версия, модели CPU/GPU, драйвер).

Посчитанные утилитой по покадровым записям `Records`: медиана FPS, **1% low и 0.1% low** (по 99-му и 99.9-му перцентилю времени кадра), среднее время кадра, средние CPU/GPU frame time, пик VRAM и **доля кадров, упёршихся в GPU** (GPU занят ≥ 90% времени кадра). Последняя метрика показывает, что CPU-тест действительно ограничен процессором, а GPU-тест — видеокартой.

Отдельной таблицей выводится **сверка**: настройки, которые бенчмарк сам записал в результат (разрешение, пресет, масштаб рендера, дальность прорисовки, RT, генерация кадров), сравниваются с запрошенными.

## Выбор настроек

### CPU-тест — минимальная работа для видеокарты, максимальная для процессора

| Настройка | Значение | Почему |
|---|---|---|
| Разрешение | 1280x720, полный экран | минимальное «стандартное» разрешение, которое поддерживает любой монитор |
| Масштаб рендера (Super Resolution) | 50% → рендер ≈ 640x360 | пикселей в 9 раз меньше, чем в 1080p; стоимость кадра для GPU почти нулевая |
| Пресет и групповые настройки (тени, GI, отражения, эффекты, пост-обработка, текстуры, AA, растительность, материалы) | Low | эти настройки нагружают в первую очередь видеокарту |
| Дальность прорисовки | **Cinematic** | больше объектов в кадре → больше draw calls, LOD/culling, анимации — это работа **процессора** (game/render thread). На 360p для GPU это почти бесплатно. Так тест сильнее различает процессоры |
| Full Ray Tracing | выкл | самая тяжёлая для GPU опция |
| Генерация кадров | выкл | дорисовывает кадры на GPU и завышает FPS, не отражая скорость CPU |
| VSync, лимит FPS, динамическое разрешение | выкл | ничто не ограничивает FPS сверху |

Логика: если GPU успевает отрисовать кадр намного быстрее, чем CPU его подготовит, FPS определяется процессором. Это проверяется по данным прогона: в отчёте видно, какую долю времени кадра GPU был занят и сколько кадров упёрлось в GPU (ожидается ≈ 0%).

### GPU-тест — максимальная нагрузка на видеокарту

| Настройка | Значение | Почему |
|---|---|---|
| Разрешение | родное разрешение монитора (`--gpu-resolution`, чтобы задать другое), полный экран | максимум пикселей, которые можно вывести на этот монитор |
| Масштаб рендера | 100% | апскейлер не уменьшает внутреннее разрешение; на 100% DLSS/FSR/XeSS работают как сглаживание в полном разрешении |
| Пресет и все групповые настройки | Cinematic | максимальное качество теней, Lumen GI, отражений, растительности, эффектов, текстур |
| Дальность прорисовки | Cinematic | больше геометрии для отрисовки |
| Full Ray Tracing (path tracing) | вкл, уровень **Very High** | самая тяжёлая нагрузка в игре: RT-ядра и шейдеры работают на пределе |
| Генерация кадров | выкл | «ненастоящие» кадры скрыли бы реальную скорость рендера |
| VSync, лимит FPS | выкл | GPU работает на 100% без пауз |

Апскейлер (DLSS / FSR / XeSS / TSR) утилита не меняет: на 100% масштаба он работает как сглаживание, а доступные варианты зависят от видеокарты. Какой апскейлер использовался, видно в отчёте (поле `Dlss` из результата бенчмарка).

## Если что-то пошло не так

- **Клики не попадают в кнопки** (например, на мониторе 21:9 или 16:10 меню расположено иначе): посмотрите в окне бенчмарка, где находятся кнопки, и передайте их координаты в долях окна: `--start-button 0.11,0.455 --confirm-button 0.39,0.59`. Если автоматика не сработала, можно один раз нажать кнопку руками — утилита всё равно дождётся и разберёт результат.
- **Меню долго грузится** (первый запуск, компиляция шейдеров): `--menu-delay 60`.
- **«Нет строки UISettingData»**: конфиг ещё не создан полностью — запустите бенчмарк вручную, откройте настройки, нажмите «Применить», выйдите.
- **Прогон прерван**: исходные настройки восстанавливаются автоматически (в том числе при следующем запуске утилиты).

## Структура проекта

```
src/WukongAutoBench/
├── Program.cs                     сценарий: поиск → backup → CPU → GPU → restore → отчёт
├── Options.cs                     параметры командной строки
├── Steam/SteamLocator.cs          Steam, библиотеки, appmanifest
├── Config/
│   ├── BenchmarkProfile.cs        профили CPU/GPU и обоснование настроек
│   ├── SettingsApplier.cs         запись профиля в три представления настроек
│   ├── IniDocument.cs             точечное редактирование ini без потери форматирования
│   ├── UiSettingData.cs           разбор/запись строки UISettingData
│   └── GameConfigFiles.cs         резервная копия и восстановление
├── Runner/
│   ├── BenchmarkRunner.cs         запуск, проход меню, ожидание результата, завершение
│   └── InputSimulator.cs          SendInput: клавиши скан-кодами, клики, активация окна
├── Results/                       разбор JSON бенчмарка, ожидание файла, расчёт метрик
├── SystemInfo/                    характеристики ПК
└── Reporting/                     отчёт: консоль, Markdown, JSON
tests/WukongAutoBench.Tests/       юнит-тесты (правка ini, разбор результатов, метрики)
```
